 リユース推進部 商品管理台帳 v6 — Google Sheets連携セットアップ手順
 （GAS方式 — Google Cloud Console・クレジットカード不要）
═══════════════════════════════════════════════════════════════

作成日: 2026年5月14日
対象拠点: 府中センター（リユース推進部）
対象ファイル: 商品管理台帳_v6.html ／ gas_server.gs

この手順書は、商品管理台帳v6 を Google Apps Script（GAS）経由で
Googleスプレッドシートと連携させ、2台のPC（入荷登録用・商品管理用）で
同じデータを共有運用するためのセットアップを案内するものです。

OAuth・Google Cloud Console・クレジットカード登録は一切不要です。
普段業務で使うGoogleアカウントだけで完結します。

─────────────────────────────────────────────────────────────────
 全体の流れ（所要時間：15〜20分程度）
─────────────────────────────────────────────────────────────────

  STEP 1.  Googleスプレッドシートを新規作成
  STEP 2.  GASエディタを開き gas_server.gs の中身を貼り付け
  STEP 3.  SECRET_KEY を任意のランダム文字列に書き換え
  STEP 4.  Webアプリとしてデプロイし、デプロイURLを取得
  STEP 5.  商品管理台帳アプリの「設定」タブにURL・シークレットを登録
  STEP 6.  「接続テスト」→「シート構成を初期化」→「アップロード」を実行
  STEP 7.  2台目のPCでも同じURL・シークレットを登録

─────────────────────────────────────────────────────────────────
 STEP 1. Googleスプレッドシートを新規作成
─────────────────────────────────────────────────────────────────

 1-1. ブラウザで以下を開く
        https://sheets.new

 1-2. 業務用Googleアカウントでログイン

 1-3. ファイル名を設定（例：「府中センター 商品管理台帳DB」）

 1-4. シート1のままでOK。アプリ側が自動で
        products / inv_checked / inv_scan の3シートを作成する

─────────────────────────────────────────────────────────────────
 STEP 2. GASエディタを開き、gas_server.gs を貼り付け
─────────────────────────────────────────────────────────────────

 2-1. 開いたスプレッドシートの上部メニュー
        「拡張機能」→「Apps Script」をクリック

 2-2. 新しいタブでGASエディタが開く

 2-3. 左側のファイル一覧に「コード.gs」（または "Code.gs"）がある。
       中の「function myFunction() { }」を全削除

 2-4. 同梱の gas_server.gs をテキストエディタで開き、
       全文をコピーしてGASエディタに貼り付ける

 2-5. プロジェクト名を変更（左上「無題のプロジェクト」をクリック）
        例:「商品管理台帳 v6 GAS API」

 2-6. 右上の「保存」アイコン（フロッピーディスク）をクリック

─────────────────────────────────────────────────────────────────
 STEP 3. SECRET_KEY を任意の文字列に書き換える
─────────────────────────────────────────────────────────────────

 3-1. GASエディタ上で、貼り付けたコードの冒頭付近にある以下の行を探す:

        const SECRET_KEY = 'CHANGE_ME_TO_LONG_RANDOM_STRING';

 3-2. 'CHANGE_ME_TO_LONG_RANDOM_STRING' の部分を、任意の長いランダム
       文字列に書き換える（最低20文字、英数字推奨）

       例:  const SECRET_KEY = 'fc-ledger-7H3kPq9NmZ2VxR4tBnQ8';

       ★ このシークレットキーは後ほどHTML側にも登録します。
         同じ値を両方に入れることで通信を保護します。

       ★ メモ帳など安全な場所に控えておくこと

 3-3. 保存（Ctrl+S または フロッピーアイコン）

─────────────────────────────────────────────────────────────────
 STEP 4. Webアプリとしてデプロイ
─────────────────────────────────────────────────────────────────

 4-1. GASエディタ右上の「デプロイ」ボタン → 「新しいデプロイ」

 4-2. 「種類の選択」（歯車アイコン）→「ウェブアプリ」を選択

 4-3. デプロイ設定
        - 説明: 任意（例「v6 GAS API 初回デプロイ」）
        - 次のユーザーとして実行:  ★「自分」★
        - アクセスできるユーザー: ★「全員」★
            ※ シークレットキーで保護するため「全員」にしてOK
            ※ ただしURLは社内のみに共有してください

 4-4. 「デプロイ」をクリック

 4-5. 初回デプロイ時はアクセス許可を求められる
        - 「アクセスを承認」をクリック
        - アカウントを選択
        - 「このアプリは Google で確認されていません」警告が表示される
        - 左下の「詳細」をクリック → 「（プロジェクト名）に移動（安全ではないページ）」
          をクリック
        - 「許可」を押す
        ★ これは自作のGASスクリプトなので警告が出ますが、本人作成の
          スクリプトなので問題ありません

 4-6. デプロイ完了画面で表示される「ウェブアプリ URL」をコピー
        例: https://script.google.com/macros/s/AKfycby.../exec

      ★ このURLを商品管理台帳の「設定」タブに貼り付けます

 4-7. 「完了」をクリック

─────────────────────────────────────────────────────────────────
 STEP 5. 商品管理台帳アプリの「設定」タブに登録
─────────────────────────────────────────────────────────────────

 5-1. 商品管理台帳_v6.html をChromeで開く

 5-2. 上部タブの「設定」をクリック

 5-3. 「接続情報」カードに
        - GASデプロイURL:  STEP 4-6 でコピーしたURL
        - シークレットキー: STEP 3-2 で設定したランダム文字列
       を貼り付けて「保存」

 5-4. 「接続テスト」をクリック
        - 緑色のトースト「GASへの接続に成功しました」が出ればOK
        - 失敗時はトラブルシューティングを参照

─────────────────────────────────────────────────────────────────
 STEP 6. シート初期化 → 全件アップロード
─────────────────────────────────────────────────────────────────

 6-1. 「データ操作」カードで「シート構成を初期化」をクリック
        - products / inv_checked / inv_scan の3シートが
          スプレッドシートに自動作成される
        - 既存のシートを上書きすることはない

 6-2. 「localStorage → クラウド（全件アップロード）」をクリック
        - 確認ダイアログ「OK」で実行
        - ローカルの476件がスプレッドシートに書き込まれる
        - 処理ログに「商品 476 件アップロード完了」と表示される

─────────────────────────────────────────────────────────────────
 STEP 7. 2台目のPCへの展開
─────────────────────────────────────────────────────────────────

 7-1. 2台目のPCに以下の2ファイルをコピー
        - 商品管理台帳_v6.html
        - README.txt（このファイル）

      ※ gas_server.gs は2台目では不要（クラウド側に既に展開済）

 7-2. Chromeで商品管理台帳_v6.html を開き「設定」タブを表示

 7-3. 1台目と同じ
        - GASデプロイURL
        - シークレットキー
       を貼り付けて「保存」→「接続テスト」

 7-4. 「クラウド → localStorage（全件取得）」をクリック
        - クラウドの476件が2台目のlocalStorageにダウンロードされる

 7-5. 商品台帳タブで件数が一致していることを確認

─────────────────────────────────────────────────────────────────
 日常運用ガイド（2台同時運用）
─────────────────────────────────────────────────────────────────

【パターンA: デュアル保存モードを使う（推奨・自動）】

  両方のPCの「設定」タブで「デュアル保存モード」をONにする。
  以後、商品登録・編集・棚卸チェック・売上登録のたびに、
  約2秒のデバウンスを挟んで自動でスプレッドシートにも保存される。

  作業前に1回「クラウド → localStorage（全件取得）」を実行し、
  もう片方のPCの変更を取り込んでおくと安全。

【パターンB: 手動同期（明示的・確実）】

  作業開始時:
    「クラウド → localStorage（全件取得）」で最新を取得
  作業終了時:
    「localStorage → クラウド（全件アップロード）」で反映

  どちらか1台でしか書き込まないようにすると競合が起きない。

【競合した場合】

  両方のPCが同じ商品を編集して両方ともアップロードした場合、
  後にアップロードした方が勝ちます（last-write-wins）。
  重要な編集はCSV出力でバックアップを取ってから実施を推奨。

─────────────────────────────────────────────────────────────────
 トラブルシューティング
─────────────────────────────────────────────────────────────────

【症状】 接続テストで「GASから不正な応答（HTMLが返されました）」
 → GASデプロイURLが間違っている、もしくはデプロイが「ウェブアプリ」で
   ない可能性。STEP 4を再実行。

【症状】 接続テストで「Invalid secret」エラー
 → シークレットキーがHTML側とGAS側で食い違っている。
   STEP 3 の SECRET_KEY と「設定」タブの値が完全一致していることを確認。
   余分なスペース・改行に注意。

【症状】 「サーバー側でSECRET_KEYが設定されていません」
 → STEP 3-2 の書き換えを忘れている。
   gas_server.gs の SECRET_KEY を初期値から変更して再デプロイ。

【症状】 シート初期化で「You do not have permission...」エラー
 → STEP 4 のデプロイで「次のユーザーとして実行: 自分」になっていない
   可能性。デプロイをやり直して「自分」を選択。

【症状】 接続テスト成功するが「アップロード」で500エラー
 → 通信が一時的に切れた可能性。再試行。
 → 件数が10000を超える場合はGASの実行時間制限(6分)に当たることがある。
   その場合は1000件ずつ分割アップロードを検討。

【症状】 デュアル保存モードONにしたのに反映されない
 → 「処理ログ」カードで「自動同期エラー」が出ていないか確認
 → URLまたはシークレットが未設定だと自動同期はスキップされる

【症状】 別PCで取得しても件数が古い
 → デュアル保存モードはデバウンス2秒。直前の操作からすぐ取得すると
   未反映の場合あり。「処理ログ」で「自動同期完了」を確認してから
   取得し直す。

─────────────────────────────────────────────────────────────────
 GASスクリプトの更新方法（バグ修正・機能追加時）
─────────────────────────────────────────────────────────────────

 1. GASエディタを開き、コードを編集して保存
 2. 右上「デプロイ」→「デプロイを管理」
 3. 既存デプロイの「鉛筆」アイコン（編集）をクリック
 4. バージョン: 「新バージョン」を選択
 5. 「デプロイ」をクリック

 ※ URLは変わらないので、HTML側の設定変更は不要

 ★ 注意：「新しいデプロイ」を作るとURLが新しくなる。
   既存のURLを維持したい場合は必ず「デプロイを管理」から
   既存デプロイを編集すること。

─────────────────────────────────────────────────────────────────
 セキュリティに関する留意事項
─────────────────────────────────────────────────────────────────

 - GASのアクセス権を「全員」にしているのは、ブラウザから直接fetch
   できるようにするため。シークレットキーで実質的なアクセス制御を行う。

 - シークレットキーは長くランダムなものを使用し、外部に漏らさないこと。
   PCの譲渡・廃棄時はChromeのキャッシュ削除（または該当HTMLを
   右クリック→開発者ツール→Application → Storage → Clear site data）
   で消去してください。

 - 万一シークレットキーが漏れた場合は、gas_server.gs の SECRET_KEY を
   新しい値に変更し、「デプロイを管理」から既存デプロイを再デプロイ。
   HTML側の「設定」タブも同じ値に更新する。

 - スプレッドシート自体の共有設定は「特定のユーザー」または
   社内ドメイン限定にしておく。GASは「自分として実行」なので
   ファイル共有を緩める必要はない。

─────────────────────────────────────────────────────────────────
 アプリ側の動作仕様（参考）
─────────────────────────────────────────────────────────────────

 シート構成:
   products      … 商品データ（全件）
   inv_checked   … 棚卸チェック状態
   inv_scan      … iPhoneスキャン結果（フェーズ4で使用）

 products シートの列順:
   id, name, brand, model, cat, rank, shelf, date,
   cost, cond, status, channel, saleDate, salePrice, desc,
   vendor(JSON), createdAt, updatedAt

 inv_checked シートの列順:
   id, checkedAt

 inv_scan シートの列順:
   scan_id, scanned_id, scanned_name, scanned_rank,
   scanned_at, device, inventory_month, upload_at

 デュアル保存モードONの動作:
   - state.products を変更する操作（登録・編集・売上・削除など）が
     起きたとき、約2秒のデバウンスを挟んで products シート全体を
     一括書き換え
   - state.invChecked を変更したときも同様
   - 高頻度の連続操作でもGAS呼出は最後の1回のみ

 LocalStorageキー:
   fc_ledger_v3  商品データ（既存・無変更）
   fc_inv_v3     棚卸チェック（既存・無変更）
   fc_gas_url    ★新規（GASデプロイURL・シークレットキー・同期モード設定）

 GAS API エンドポイント:
   GET  ?action=ping              接続確認
   POST  action=init               シート構成を初期化
   GET  ?action=getAll             products全件取得
   POST  action=saveAll            products全件上書き（body.data: 商品配列）
   POST  action=addOne             products 1件追加（body.data: 商品オブジェクト）
   POST  action=updateOne          管理番号で1件更新（body.data: 商品オブジェクト）
   POST  action=deleteOne          管理番号で1件削除（body.data: {id}）
   GET  ?action=getInvChecked      inv_checked取得（{id:true}形式）
   POST  action=saveInvChecked     inv_checked上書き（body.data: {id:true}）
   GET  ?action=getInvScan         inv_scan取得（オブジェクト配列）
   POST  action=addInvScan         inv_scan追記（body.data: 1件 or 配列）

 全リクエストにシークレットキーを付与:
   GET:  クエリ ?secret=YOUR_SECRET
   POST: bodyのJSON内 {secret: "YOUR_SECRET", action: "...", data: ...}

═══════════════════════════════════════════════════════════════
 【フェーズ4】scan.html — iPhone用QRスキャン画面
═══════════════════════════════════════════════════════════════

scan.html は商品管理台帳_v6.html とは独立した、iPhone Safariで動作する
QRスキャン専用の単一HTMLファイルです。フェーズ3-Bでセットアップした
同じGASデプロイURL・シークレットキーを共用してGoogleスプレッドシートに
アクセスします（OAuth・クライアントID不要）。

─────────────────────────────────────────────────────────────────
 scan.html のセットアップ手順
─────────────────────────────────────────────────────────────────

【iPhoneへの配布】

  方法A: AirDrop（推奨・最もシンプル）
    1. Macで scan.html を右クリック →「共有」→ AirDrop
    2. iPhoneを選択して送信
    3. iPhone側で「ファイル」アプリに保存

  方法B: iCloud Drive 経由
    1. scan.html を Mac の iCloud Drive にコピー
    2. iPhoneの「ファイル」アプリ → iCloud Drive で開く

  方法C: メール添付
    1. 自分宛にscan.htmlをメール送信
    2. iPhoneで添付ファイルを開いて保存

【Safariで開く】

  1. iPhoneの「ファイル」アプリで scan.html を長押し
  2.「共有」→「Safariで開く」を選択
     ※「コピー」「クイックルック」ではなく必ず「Safariで開く」

  ※ Safari以外（Chrome等）ではカメラ起動に制限がかかる場合があります

【初回起動時の設定】

  1. 右上の歯車アイコン（⚙）をタップ → 設定画面が下から表示される
  2. 以下を入力:
       - GASデプロイURL    : v6.html と同じURL（フェーズ3-Bで取得済）
       - シークレットキー  : gas_server.gs の SECRET_KEY と同じ値
       - 棚卸対象月        : 通常は当月のまま（デフォルト）
  3.「保存」をタップ
  4.「接続テスト」をタップ → 緑トースト「接続OK」が出ればOK
  5. 続けて「商品データを取得（getAll）」をタップ
        → キャッシュ件数が表示されればOK（例: 476 件）
  6. 設定画面を閉じる（×ボタンまたは画面外をタップ）

─────────────────────────────────────────────────────────────────
 モード① 商品照会モードの使い方
─────────────────────────────────────────────────────────────────

  在庫確認・商品情報の即時参照に使います。

  1. 上部タブ「商品照会」が選択されていることを確認
  2.「カメラ起動」をタップ
       → 初回はカメラ権限のダイアログが表示される → 「許可」
  3. QRコードを画面中央の枠内に映す
  4. 自動で読み取られ、商品情報がカードで表示される
  5. ステータスが色で示される:
       - 緑（在庫中）
       - 青（販売済）
       - グレー（キャンセル）
  6. 連続してスキャンすると表示が次の商品に切り替わる

  ▼ 該当商品が見つからない場合
     赤いエラーボックスに「該当する管理番号が見つかりません」と表示

  ▼ データが古い場合（PC側で追加した商品が出ない等）
     設定 → 「商品データを取得（getAll）」で最新のデータを取得し直す

─────────────────────────────────────────────────────────────────
 モード② 棚卸スキャンモードの使い方
─────────────────────────────────────────────────────────────────

  月次棚卸の実在庫確認に使います。インターネット不通でも動作します。

  1. 上部タブ「棚卸スキャン」に切替
  2.「カメラ起動」 → 商品QRをスキャン
  3. スキャンするたびに、画面下部のリストに追加されていく
        - 表示項目: 管理番号 / 商品名 / ランク / スキャン日時
        - 振動でフィードバック
        - 同じ管理番号を再スキャンすると重複警告（振動パターンも変化）
  4. 誤スキャンした場合は、リスト右端のゴミ箱アイコンで個別削除
  5. 棚卸作業終了後、「PC側に送信」をタップ
        → inv_scan シートに一括アップロード
        → アップロード後もスマホ内のデータは残る（✓送信済 と表示）
  6. 月末に「照合レポート」をタップ
        → 在庫データ × スキャン結果を比較した .xlsx をダウンロード

  ▼ オフライン運用（電波が届かない倉庫）
     IndexedDBに保存されるため、ネット未接続でもスキャン蓄積可能。
     電波が届く場所に戻ってから「PC側に送信」を実行。

  ▼ 履歴を全削除したいとき
     「スマホ内のスキャン履歴を全削除」をタップ
     （Google Sheets側のデータには影響しません）

─────────────────────────────────────────────────────────────────
 照合レポート（.xlsx）の構成
─────────────────────────────────────────────────────────────────

  ファイル名: 棚卸照合_YYYYMM_府中センター.xlsx

  ▼ シート1「照合結果一覧」（オートフィルター付き）
     A列「分類」をフィルタすると4分類で絞り込み可能:
       - 一致               : システム在庫中 ＋ スキャン済み
       - 未スキャン         : システム在庫中 ＋ スキャンされていない
       - 販売済なのにスキャン : システム販売済 なのにスキャンされた
       - 不明品             : スキャンされたがシステムに存在しない

     ※ Excel（Community SheetJS）の制限により、セル背景色は出力
        されません。「分類」列でフィルタしてご利用ください。
        必要に応じて Excel 側で「条件付き書式」で色を付けることが可能。

  ▼ シート2「差異サマリー」
     各分類の件数・割合、参考情報（スキャン総数・対象月など）

  ▼ シート3「不明品リスト」
     システムに存在しない管理番号のスキャン記録のみ抽出

─────────────────────────────────────────────────────────────────
 トラブルシューティング（scan.html）
─────────────────────────────────────────────────────────────────

【症状】「カメラ起動」をタップしても画面が真っ黒
 → 設定 → Safari → カメラ →「許可」になっているか確認
 → scan.html を一度閉じて再度Safariで開き直す
 → 他のアプリ（FaceTime等）がカメラを使用中の可能性。終了してから再試行

【症状】 カメラ権限ダイアログが出ない
 → file:// 経由でカメラが拒否されている場合があります。
   AirDropで送り直して、必ず「ファイル」アプリ→「Safariで開く」で起動

【症状】「接続OK」になるが「商品データを取得」で失敗
 → 一度に取得する件数が多すぎる可能性。
   v6.html側で「シート構成を初期化」を実行してデータを整理してから再試行

【症状】 該当商品が見つからない（PCで登録したばかりの商品）
 → 設定 →「商品データを取得（getAll）」で最新化
 → v6.html でデュアル保存モードがONか、もしくは手動アップロード済か確認

【症状】 同じ商品を二重スキャンしたのに警告が出ない
 → 「スマホ内のスキャン履歴を全削除」されている可能性
   IndexedDB に履歴が残っていないと重複検知できません

【症状】「PC側に送信」が失敗
 → 設定タブ → 「接続テスト」で疎通確認
 → GAS側でinv_scanシートが存在するか確認（v6.htmlの「シート構成を初期化」）

【症状】 QRコードが読み取れない
 → 画面の枠内にQRが収まる位置・距離で構える
 → 明るい場所で実施（暗いと読み取り精度が下がる）
 → QRが汚れていないか・反射していないか確認
